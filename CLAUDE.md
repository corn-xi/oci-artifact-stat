# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This directory contains `harbor-image-stat.sh` (formerly `harbor.sh`, then `harbor-version-audit.sh`), a standalone Bash script that reports the actual highest-published version of every image in a Harbor project (via its REST API v2.0), flagging stale/duplicate publish anomalies along the way (e.g. an old/placeholder tag re-pushed more recently than a real release). The registry is not tied to any one instance — `HARBOR_URL` is a required environment variable with no baked-in default (see below). "Image" specifically means artifacts with `type == "IMAGE"` — Harbor repositories can hold other OCI artifact types (e.g. Helm charts) under the same path, which the script filters out when picking a version (see `process_repository()`).

There is no build system, package manifest, or test suite — this is a single-file operational script, run directly from the shell.

## Running the script

```bash
./harbor-image-stat.sh [--raw-tags] <project_id_or_name>
./harbor-image-stat.sh --list-projects   # don't know the project? list what you can access
./harbor-image-stat.sh --help            # or -h; full option/env-var reference, exits 0
./harbor-image-stat.sh --version         # or -V; prints "harbor-image-stat.sh X.Y.Z", exits 0
```

- `SCRIPT_VERSION` (top of file, semantic versioning) is the single source of truth for `-V`/`--version`'s output. Bump MAJOR on a breaking CLI/env-var/output-format change, MINOR on a backward-compatible feature addition, PATCH on a fix.
- `-h`/`--help` and `-V`/`--version` are checked first in the arg-parsing loop and exit before `check_dependencies()` or `prompt_credentials()` ever run — both must work in a broken/minimal environment (that's the point of `--version` diagnostically) and must never prompt for a password. This is also why `--version` builds the program name with `${0##*/}`, not `` `basename "$0"` `` — `basename` is itself an external command that isn't in `check_dependencies()`'s list and doesn't run before this flag anyway.
- `check_dependencies()` runs right after arg parsing (so `--help` stays dependency-free) and before `prompt_credentials()` (no point asking for a password the script can't use) — `command -v`-checks `curl`/`jq`/`mktemp` and reports every missing one in a single `[FAIL]` line, exiting `127`. This exists because letting a missing tool surface naturally produces a confusing cascade instead of a clear error — see the `new_tmp()` note below.
- `--list-projects` lists every project visible to the authenticated credentials (ID, name, repo count, visibility) and exits — deliberately a separate opt-in flag rather than "no arguments" triggering it, so a missing `<project_id_or_name>` still fails fast with a clear error (important for scripted/CI callers) instead of silently changing into a listing. The "Missing argument" error message itself points at `--list-projects` so a human hitting it interactively isn't left guessing. It still requires credentials (`GET /projects` is authenticated) and still goes through `prompt_credentials()`, but skips `resolve_project()` entirely. Reuses `fetch_all_pages()` as-is — Harbor's `GET /projects` is paginated the same way as `/repositories`, and for a non-admin caller is already scoped server-side to projects they hold some role in, so no client-side filtering is needed.
- No credentials are hardcoded in the file. `prompt_credentials()` interactively asks for username (plain) and password (hidden, via `read -rs`) unless `HARBOR_USER`/`HARBOR_PASSWORD` are already set in the environment — set them beforehand to run non-interactively (e.g. from automation).
- `--raw-tags` shows the exact tag as pushed to Harbor in `VER.` (e.g. `2.18.0-rel-build42`); by default `VER.` shows the parsed `X.Y.Z` only (via `friendly_version()`), since many repositories in this registry only ever publish a component-qualified tag and the qualifier is noise for a human scanning versions. If a tag isn't semver-shaped at all, both modes show it unchanged — there's nothing to parse.
- `HARBOR_URL` is required (no default — set it explicitly, e.g. `https://harbor.example.com`); required-ness is enforced inside `main()`, not at top-level script scope, specifically so `-h`/`--help` and `-V`/`--version` keep working with zero configuration. `NO_COLOR` disables ANSI-colored status tags; `CURL_CONNECT_TIMEOUT`/`CURL_MAX_TIME`/`CURL_RETRY`/`CURL_RETRY_DELAY` tune the bounds on every `curl` call (defaults: 5s/15s/1 retry/2s — worst case ~32s per request). Retries only happen on transient failures (no response, or a 5xx) and are logged live to stderr as they happen via `curl_with_retry()` (e.g. `[WARN] 'my-repo' artifacts failed (HTTP 503) -- retry 1/1 in 2s...`), so a slow/flaky repository is visible instead of looking hung; a 4xx is never retried. The log line uses a short caller-supplied label, not the full URL — a raw URL with query string is long enough to blow past the table's column width and break the layout when it interleaves with the stdout table on the same terminal.
- Accepts either a numeric Harbor project ID or a project name string.
- Requires `bash`, `curl`, and `jq` on PATH (plus standard `mktemp`) — verified up front by `check_dependencies()`, which exits `127` with one clear message naming every missing tool rather than letting the script fail confusingly partway through.
- Uses `mktemp` for all transient response/header files and cleans them up via an `EXIT`/`INT`/`TERM` trap — no fixed filenames are written to the working directory.
- Exits non-zero if any individual repository's artifact fetch fails (tracked via `FAIL_COUNT`), even though it keeps processing the remaining repositories.

## Architecture

The script is organized into named functions, run as a pipeline against the Harbor v2.0 API:

1. **`resolve_project()`** — if the argument looks numeric, it's treated as a project ID and the script fetches `/projects/{id}` to get the name; otherwise it's treated as a name and the script fetches `/projects?name=...` to get the ID. Both directions are needed because later steps require the project *name* (for listing repositories) but the ID is what's echoed back to the user. Note: the name-lookup path relies on Harbor's fuzzy/substring `name=` filter, so the resolved `PROJECT_ID` isn't guaranteed exact — but it's only used for the confirmation banner, never for data queries, so this doesn't affect correctness of the output.
2. **`fetch_all_pages()`** — lists repositories under the project via `/repositories?project_name=...`, looping over `page=`/`page_size=100` until Harbor's `X-Total-Count` response header (with a short-page fallback) indicates everything has been fetched. This is a required step, not optional: Harbor's list endpoints are paginated, and a single unpaginated call silently drops any repositories beyond the first page — this was the root cause of "missing images" in the original version of this script. Results are still filtered client-side to only those whose `name` is prefixed with `"{PROJECT_NAME}/"`, then that prefix is stripped for display — this filter is load-bearing since the `/repositories` endpoint is not reliably scoped by `project_name` alone. Also reused by **`list_projects()`** (`--list-projects`) against the bare `/projects` endpoint — `fetch_all_pages()` picks `?` vs `&` as the pagination-param separator based on whether `BASE_URL` already has a query string, so it works for both a URL that already has one (`/repositories?project_name=X`) and one that doesn't (`/projects`).
3. **`process_repository()` + `pick_version_tag()`** — for each repository, calls `/projects/{name}/repositories/{repo}/artifacts?page_size=20&with_tag=true&sort=-push_time` (repo name URL-encoded via `jq -sRr @uri` to handle slashes). `sort=-push_time` is required but not sufficient on its own — Harbor doesn't guarantee push order matches version order (a stale/un-bumped tag can easily be the most recently pushed artifact), so `pick_version_tag()` pools tags across the whole fetched window (excluding non-`IMAGE`-type artifacts, e.g. a Helm chart published under the same repo path) and picks the tag with the numerically highest `(major, minor, patch)` — not the first one encountered by push time. When multiple tags tie on that number (the same release multi-tagged with both a plain and a component-qualified name), the shortest tag wins. `semver_key()` normalizes a tag to `"major.minor.patch"` for comparison; `friendly_version()` reuses it to strip qualifier suffixes for display. Non-200 responses are counted in `FAIL_COUNT` (distinct from `EMPTY_COUNT`, so real API failures are never misreported as "no tags") and still produce a table row (`STATUS = FAIL`) rather than silently vanishing.

Auth is HTTP Basic, built once at the top of the script as a base64-encoded `user:pass` string (from `HARBOR_USER`/`HARBOR_PASSWORD`) and reused in every `curl` call via `curl_with_retry()` (which `harbor_get()` and `fetch_all_pages()` both call). Every attempt carries `--connect-timeout`/`--max-time` from `CURL_OPTS`; retrying is handled by `curl_with_retry()` itself (not curl's own `--retry`) specifically so each retry can be logged, and only for transient outcomes (`000`/no response, or 5xx) — a 4xx is returned immediately since retrying can't fix a bad request/auth/404.

Output uses fixed-width bracketed status tags (`log_ok`/`log_fail`/`log_warn`/`log_info` → `[ OK ]`/`[FAIL]`/`[WARN]`/`[INFO]`) for top-level banners, and a 3-column `IMAGE` / `VER.` / `STATUS` table (`STATUS` ∈ `OK`/`WARN`/`FAIL`/`EMPTY`) for per-repository rows. The table is rendered in two passes: `process_repository()` appends each row to the `ROW_NAMES`/`ROW_VERSIONS`/`ROW_STATUSES`/`ROW_STATUS_COLORS` arrays instead of printing directly, then `render_table()` (called once, after the loop) sizes the `IMAGE` and `VER.` columns to the longest actual value before printing anything — a fixed width breaks alignment the moment content exceeds it, which is exactly what happened with `--raw-tags`' longer tag strings. Per-repository diagnostics (why something is `WARN`/`FAIL`) are **not** printed inline with the row either — they're appended to the `DETAIL_LINES` array and printed once, together, in a `Details:` block after the table, so the table itself stays a single scannable grid. Color is gated behind `[ -t 1 ] && [ -z "$NO_COLOR" ]` so it degrades to plain ASCII when piped.

## Notes for future edits

- Targets bash 3.2 (macOS's system `/bin/bash`, still shipped due to GPLv3 licensing) as the floor, not just whatever `bash` the developer's shell resolves to via the `#!/usr/bin/env bash` shebang (Homebrew bash 5.x on most dev machines). Bash < 4.4 throws "unbound variable" under `set -u` when a *bare* `"${arr[@]}"` is expanded on a zero-element array — hit this for real in `curl_with_retry()`'s `extra_args` (empty on most calls) and in `render_table()`'s `ROW_NAMES`/`ROW_VERSIONS` (empty when a project has zero repositories). The naive fix, `"${arr[@]:-}"`, is only sometimes correct: on an empty array it yields one *empty-string* word, not zero words -- harmless in a plain `for` loop (an empty `n` just fails every length check) but fatal when handed to `curl` as a positional argument (`curl: option : blank argument where content is expected`). So: use `"${arr[@]:-}"` for plain iteration, but for anything spliced into an external command's argv, check `"${#arr[@]}" -gt 0` first and conditionally append (`${#arr[@]}` is always safe under `set -u`, even empty) -- see `curl_with_retry()`'s `curl_args` construction for the pattern.
- All user-facing output and comments are in English.
- The main repository loop uses process substitution (`done < <(jq -c '.[]' <<<"$repositories")`), not a pipe into `while read` — this matters because the script accumulates `OK_COUNT`/`WARN_COUNT`/`FAIL_COUNT`/`EMPTY_COUNT` counters inside the loop that must survive to the final summary; a piped `while` would run in a subshell and lose them.
- The final summary line's four counters map 1:1 to the `STATUS` column's possible values and always sum to the number of rows printed (`Total: N repositories -- OK: .., WARN: .., FAIL: .., EMPTY: ..`) — deliberately, since an earlier version's "Total: N images" only counted successes and silently excluded `FAIL` rows, which read as "N images in the project" when it actually meant "N successfully processed."
- `cleanup()` (the `EXIT` trap) must always return 0 — an earlier draft had it end on a conditional test (`[ -n "$f" ] && rm -f "$f"`) whose exit status, when `TMP_FILES` was empty, would override the script's real exit code under `set -e`. Keep this in mind if editing the trap.
- `set -euo pipefail` is active; per-repository failures inside `process_repository()` must be handled explicitly (checked `if`/`return`, not a bare failing command) so one bad repository doesn't abort the whole run.
- `log_warn`/`log_fail` write to stderr, not stdout — this is required, not stylistic: `curl_with_retry()`'s stdout is captured via `$(...)` to get the HTTP status code back to its caller, so anything it prints to stdout gets appended into that "return value" instead of appearing on screen. This exact bug happened once already (retry log lines got concatenated into the `$http_code` variable). If you add new diagnostic logging inside any function whose stdout is captured for a return value, it must go to stderr.
- `set -e` does **not** reliably propagate through a failing command nested inside a function that is itself invoked via command substitution (confirmed by direct reproduction: `f() { x=$(false_cmd); }; y=$(f)` does not stop the script, even under `set -euo pipefail`). Every function in this script that does real work is called exactly that way (`body_file=$(new_tmp)`, `http_code=$(harbor_get ...)`, etc.), so a bare failing command inside one of them can silently continue with an empty/garbage result instead of halting — this is what happened when `mktemp` failed inside `new_tmp()`: `f` silently became `""`, which then corrupted every downstream `curl -o "$body_file"` call with a blank argument, producing a confusing cascade of unrelated-looking `curl`/`sleep` errors instead of one clear failure at the source. The fix is always the same: don't trust propagation — check explicitly and `exit` (not just `return`) on failure, e.g. `f=$(mktemp) || { log_fail "..."; exit 1; }` in `new_tmp()`. An explicit `exit` inside a nested command substitution *does* correctly terminate the whole script (also confirmed by reproduction) — it's only the implicit, unchecked failure of an inner command that gets swallowed. `check_dependencies()` exists specifically to catch the common case (a tool missing entirely) before any of this fragile machinery runs at all; the explicit check in `new_tmp()` is defense in depth for the rarer case where the binary exists but a specific invocation still fails (e.g. `/tmp` not writable, a bad `TMPDIR`).
